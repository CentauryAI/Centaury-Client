# centaury — map for AI agents

Thin client: connections + UI only, zero business logic (all logic server-side, anti-leak split). Talks to centaury-server via HTTP + WS using `centaury-protocol` wire types.

## Identity model

Two token kinds, both files under `$KORE_DIR`:
- **session** (`$KORE_DIR/session`) — human login (24h), only used to mint instance tokens via `human` cmd.
- **instance token** — everything else authenticates with this. Resolution: `KORE_TOKEN_FILE` → named-agent path `$KORE_DIR/[<project>/]agents/<name>.token` when `KORE_NAME` set → `$KORE_DIR/<project>/token` → global `$KORE_DIR/token`. `launch` ALWAYS sets `KORE_NAME` (derived name if no `--name`) so a spawned agent can never load the human's token and speak as them; hooks also re-register on KORE_NAME↔token-sub mismatch.

Instance name displayed = JWT `sub` decoded unverified (config.rs `instance_name`) — display only, server verifies.

## Typical human flow

```
centaury signup you@co.com --name You [--business]   # prints org reg secret ONCE
centaury login you@co.com

                                 # is your account's owner_name (server-assigned,
                                 # DU-S2; response body carries it)

centaury tui
```

Env the hooks/agents read: `KORE_SERVER_URL`, `KORE_REG_SECRET`, `KORE_ORG`, `KORE_PROJECT`, `KORE_OWNER`, `KORE_NAME`, `KORE_TAG`, `KORE_HOOK_TIMEOUT`, `KORE_TOKEN_FILE`, `KORE_DIR`, `KORE_AUTO_TRUST` (=0 opts out of HC5 launch workspace auto-trust).

## Invariants

- The project is THE sealed bubble (see server/CLAUDE.md "Isolation") — client just passes `--project`; server enforces. Groups/sector removed 2026-07-05.
- Hooks must never break the agent: unknown events succeed silently, status posts are fire-and-forget, unreachable server = agent stops normally (hook.rs).
- Task subagents never touch identity (G2): SessionStart fires only for real sessions, so subagents can't auto-register; `SubagentStop` is an explicit no-op in `dispatch_stdin_event` — never route it to `stop_poll` (would block the subagent and ack the parent's inbox as the parent; subagents inherit KORE_* env). Pinned by `subagent_stop_is_a_silent_noop`.
- Auto-registered agent name is deterministic (host+cwd+project hash) so retries never mint duplicates (hook.rs `auto_name`); rendered as a 4-letter CVCV word like legacy (config.rs `derived_name`), never hardcode agent names in docs.
- One consuming listener per identity: server kicks the old WS (code 4000); `listen` exits on it, TUI avoids the fight entirely via peek.
- Password prompt: tty → rpassword, piped stdin → read line (scripts/CI) — auth.rs `read_password`.
- TLS = rustls (Cargo.toml), never native-tls: the release binary is static musl with zero system deps (P5, DECISIONS "Release pipeline"). Release flow: tag `v*` (must equal client/Cargo.toml version — CI guard) → `.github/workflows/release.yml` builds the 4-target matrix (linux musl static, mac arm64+x86_64, windows msvc) + syncs `client/`+`protocol/`+`mirror/` skeleton (install.sh + install.ps1) to the public mirror repo and publishes the binaries there; `workflow_dispatch` = build-only dry run. Windows compiles via one cfg gate (hook.rs `spawn_waker` no-op — unix-only terminal pokes); dry-run before the first tag, the windows leg is CI-verified only (P5b).
